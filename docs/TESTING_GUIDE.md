## 2. Database Setup

The project uses Cloudflare D1 (SQLite). Locally, Wrangler emulates D1 in `.wrangler/state/v3/d1/`.

### 2.1 Verify Migration File Exists

**ACTION:**
```powershell
Get-Item "c:\Users\User\Desktop\Email Leads\drizzle\0000_perpetual_sentry.sql"
```

**EXPECTED RESULT:** File exists, size > 0.

**FAILURE INDICATION:** "Cannot find path" — run `npm run db:generate` to regenerate.

### 2.2 Apply Migration Locally

Wrangler applies the migration automatically when the dev server first starts. To apply manually:

**ACTION:**
```powershell
cd "c:\Users\User\Desktop\Email Leads"
npx wrangler d1 execute DB --local --file drizzle/0000_perpetual_sentry.sql
```

**EXPECTED RESULT:** Output shows statements executed with no errors.

**FAILURE INDICATION:** `Error: No D1 database with name "DB"` — the `wrangler.json` in `dist/server/` is generated by the build step. Run `npm run build` first, then re-run the migration command.

### 2.3 Verify Schema Test

**ACTION:**
```powershell
cd "c:\Users\User\Desktop\Email Leads"
node --test --experimental-strip-types scripts/schema.test.mjs
```

**EXPECTED RESULT:**
```
✔ Migration enforces tenant-scoped email uniqueness and campaign deduplication
✔ Database batch transaction rolls back duplicate inbound event side effects
```

**FAILURE INDICATION:** Any `✗` or stack trace — the migration SQL is broken.

The local development environment uses a loopback-only identity provided by the ChatGPT/OpenAI Sites starter. It does not require real credentials.

**ACTION:**
1. Open `http://localhost:5173` in a browser (Chrome, Edge, or Firefox)

- Redirect loop — the local identity provider is not running properly. Restart `npm run dev`.

**ACTION:** Open a new incognito/private browser window and navigate to `http://localhost:5173/api/workspace` directly (GET request, no auth).

## 10. Lead Generation (API Provider)

> **Note:** This feature requires `LEAD_API_URL` and `LEAD_API_KEY` to be set. Without them, the Generate button is disabled. The section below covers both the disabled state and the configured state.

### 10.1 Verify Disabled State (No Provider Configured)

**ACTION:** Click **Generate leads** button (top right of Leads view).

**EXPECTED RESULT:** The generate dialog opens. It shows a notice: "Connect a licensed lead provider first." The **Generate leads** button inside the dialog is **disabled** (grayed out).

**FAILURE INDICATION:** Button is enabled or no notice shown — guard condition is broken.

### 10.2 Test With a Mock Provider

To test the generate flow without a real provider, create a local mock endpoint.

**ACTION:**
1. Create a simple HTTPS server or use a service like `https://httpbin.org` — actually, to test locally, set up a simple Node server that returns the expected format. Alternatively, for a quick check use a service like RequestBin + ngrok.
2. Point your mock to return:
```json
{
  "leads": [
    {
      "name": "Generated Lead",
      "email": "generated@test.com",
      "phone": "555-9999",
      "state": "Texas",
      "city": "Austin",
      "type": "Insurance consumer",
      "skills": "",
      "experience": "",
      "source": "Mock provider",
      "sourceUrl": "",
      "permission": "Opted in"
    }
  ]
}
```
3. Set in your local `.env` (or Wrangler secrets):
   - `LEAD_API_URL=https://your-mock-endpoint/leads`
   - `LEAD_API_KEY=test-key`
4. Restart the dev server
5. Open Generate leads, fill Industry=Life Insurance, State=Texas, Limit=1
6. Click **Generate leads**

**EXPECTED RESULT:** Toast: "1 leads imported · 0 duplicates skipped". New lead appears in table with source "Mock provider".

**FAILURE INDICATION:**
- 409 "Connect a licensed data provider" — env vars not loaded, restart dev server
- 502 "Lead provider returned..." — mock endpoint not responding correctly
- 502 "Provider returned an invalid response" — mock response format wrong (must return `{ "leads": [...] }`)

## 15. SendGrid Setup

> These steps happen in the SendGrid dashboard, not in the application code.

### 15.1 Required SendGrid Configuration

| Step | Where | What to do |
|---|---|---|
| Create API key | sendgrid.com → Settings → API Keys | Create Full Access key. Save value as `SENDGRID_API_KEY`. |
| Verify sender domain | Settings → Sender Authentication | Authenticate the domain you'll send from. Add DNS records. Wait for verification. |
| Create verified sender | Settings → Sender Authentication → Single Sender | For testing: verify a single sender email. |
| Event webhook | Settings → Mail Settings → Event Webhook | Set URL to `https://yourapp.com/api/sendgrid/events`. Enable Signed Event Webhook. Save public key as `SENDGRID_EVENT_PUBLIC_KEY`. |
| Inbound parse | Settings → Inbound Parse | Add MX records for your subdomain. Set webhook URL to `https://yourapp.com/api/sendgrid/parse`. Enable signed parse webhook. Save key as `SENDGRID_PARSE_PUBLIC_KEY`. |

### 15.2 Set Environment Variables

Set these in your Cloudflare deployment environment (not committed to `.env`):

```
SENDGRID_API_KEY=SG.xxxxx
APP_URL=https://yourapp.openai.com
UNSUBSCRIBE_SECRET=<32+ byte random hex>
LIVE_SEND_ENABLED=true
```

Generate secrets:
```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### 15.3 Verify Connection Status

**ACTION:** Open the app, navigate to **Data sources** tab.

**EXPECTED RESULT:** "Email delivery" card shows status **Connected** (green badge). If still "Not connected", the env vars are not loaded.

**FAILURE INDICATION:** Still shows "Not connected" — restart the server after setting env vars.

$secret = "your-INBOUND_WEBHOOK_SECRET-value"

$body = '{"id":"test-event-001","type":"reply","deliveryId":"REPLACE-WITH-REAL-DELIVERY-UUID","subject":"Test Reply","body":"I am interested, please send details."}'
$hmacKey = [System.Text.Encoding]::UTF8.GetBytes($secret)

$hmac = New-Object System.Security.Cryptography.HMACSHA256

$hash = $hmac.ComputeHash($message)
$sig = [BitConverter]::ToString($hash).Replace("-","").ToLower()
$response = Invoke-RestMethod -Uri "http://localhost:5173/api/inbound" -Method POST -Headers @{"x-leadflow-timestamp"=$stamp;"x-leadflow-signature"=$sig;"Content-Type"="application/json"} -Body $body

- 401 "Expired signature" — timestamp is more than 5 minutes old
- 404 "Delivery not found" — `deliveryId` is not a real delivery UUID in the database
